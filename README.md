# 侧边栏管理 · dsh-sidebar

用于 DeepSeek Harness 的侧边栏导航管理插件。

## 使用

安装后刷新应用，在 **设置 → 侧边栏管理** 中操作：

- 分别调整主侧边栏功能入口、设置侧边栏页面的排列顺序。
- 原本位于头像上方的底部插件入口（例如「whaleness移动设备」）也纳入主侧边栏，可与其他入口一起排序、隐藏或收入「更多」，不再单独固定在底部。
- 使用上下箭头排序，使用开关显示或隐藏项目。
- 点击菜单名称可直接编辑，按 Enter 或离开输入框保存；清空或点击「恢复原名」恢复插件提供的名称。主侧边栏、设置侧边栏及「更多」名称均可修改，最多 80 字。
- 「更多」内的普通面板和底部插件动作与原生「浏览更多插件 / 创建你的插件」对齐，统一使用 14px 图标、13px 字号、20px 行高、34px 行高区域及 8px 左右内边距，图标和文案左对齐。
- 本插件的设置入口始终显示，不能隐藏；允许排序。
- 主侧边栏列表中包含「更多」，开关固定开启且不可修改，但可以上下排序。
- 「更多」是收纳分界线：排在上面的菜单直接显示在侧边栏，排在下面的菜单只出现在「更多」菜单中；移回上方即可展开。
- 收入「更多」的菜单保持顺序、点击跳转和当前页面标记；原有的浏览/创建插件等菜单动作保留。
- 支持重置单个列表或恢复全部默认值。
- 名称、排序、显隐和恢复默认均立即预览，异步保存到插件配置，无需额外点击应用；显示读取中、保存中、已保存、只读或失败状态。保存失败时回退到服务端已确认的配置。
- 新注册的功能入口会自动出现在列表中，隐藏项目不会停用对应插件。

主侧边栏的「新会话」和底部头像设置入口保留原有位置，不属于功能入口列表。底部插件动作的原生控件及点击逻辑保持不变，不会被当作面板路由跳转；新入口按现有的新增项目规则加入列表。隐藏的项目既不会显示在侧边栏，也不会进入「更多」。旧配置中的「更多」默认追加在末尾；恢复默认时也回到末尾。

## 保存范围

名称、排序和显隐统一保存在 DSH 当前 profile 的本插件 `config.preferences` 中，通过公开的 `configForms` 服务读写。DSH 配置编辑器将变更写入当前 profile 的配置补丁，而不是修改本插件随包发布的配置模板。相同 profile 的其他浏览器也读取这份配置，刷新和重启后保留；不同 profile 仍互相独立。并发修订、写入权限及原子持久化由 DSH settings 服务处理；客户端提交完整 preferences 字段，确保清空名称及重置真正删除旧覆盖。

旧版浏览器配置 `dsh-sidebar.preferences.v1` 仅用于一次性迁移：当服务端没有 preferences、当前连接可写时，将旧名称/排序/显隐写入插件配置；只有服务端确认保存成功后才删除旧本地数据。服务端已有配置（包括显式恢复默认后的空配置）时，不用本地数据覆盖它。浏览器存储不可用不影响新配置的正常保存。

本次升级增加了服务端配置 schema，建议重启 DSH 一次再使用。若管理页提示「插件配置尚不可用」，请重启应用，而非只刷新页面。后续偏好修改为动态配置，无需再次重启。

## 开发

仅依赖 DSH 使用的 `@deepseek-ai/schemastery` 配置 schema 库，不修改 DSH 安装目录或原有插件。

```sh
npm ci --ignore-scripts
npm run build
npm test
```

使用 Harness 的插件管理器安装本目录即可。本地目录以链接方式安装，不要删除或移动工作目录。修改客户端代码后重新构建，并刷新应用；是否需要重启取决于插件管理器返回的安装状态。

## 实现与兼容性

针对 DSH `0.2.1-rc.5` 的导航结构实现。该版本没有公开的全局导航过滤接口，且子 Slot 只能由一个注册项声明；旧实现复制父级的子 Slot 声明会引发 `already declared` 错误，现已移除。

当前使用一个版本相关、可撤销的兼容适配层：在原注册项上临时包装组件，投影 `usePanels` / `useSections` 的结果，并按「更多」分界线派生 `useEntryPins`。折叠菜单通过公开的 `sidebar.panellist.actions` 插槽追加，不复制已有子 Slot。针对原应用强制固定「插件」入口的特例，使用仅限展示层的别名并将图标、选中状态和跳转映射回真实 ID。原来的子 Slot 所有权、注入器、语言、存储句柄和动作保持不变。该适配层不是官方稳定扩展接口。

底部动作通过公开的 `sidebar.footer.action` 插槽发现，使用独立命名空间保存 ID，避免与面板 ID 冲突。适配层还会在独立 React 边界内投影原侧边栏返回的元素树，将对应的面板行替换为原动作插槽的完整控件，并停止原底部位置的重复渲染；「更多」中也使用原控件，不嵌套按钮、不伪造点击或面板路由。此投影依赖 rc.5 的行属性结构。带有明确 label 的底部入口按菜单管理，其原生控件以 `wide: false` 提供图标和点击逻辑，由本插件统一行样式及展示名称（适配标准的根 button 控件）；不改变它的动作和路由。未提供 label 的状态控件不作为菜单收入列表，而是保留原来的底部渲染及条件显示行为。例如内置 `cordis-panel` 在没有运行项目时返回空内容，不能把它的注册 ID 当作一个可见菜单名称。

不使用 DOM 查询或改写，不导入 Harness 客户端内部模块，不改写方法原型。卸载时恢复组件引用并清理订阅、事件监听；展示偏好保留以供重新启用。更新客户端代码后须刷新整个应用页面。

此方式依赖原有组件的快照 Hook 名称及可写的组件引用，DSH 更新后若结构改变需重新验证。本插件保护的是自身导航入口，用户仍然可以从插件管理器主动停用或卸载本插件。

## 验证

- 单元测试覆盖默认排序、显隐、入口保护、重排、无效配置、恢复默认、组件适配清理，以及「更多」分界、旧配置迁移、跨分界移动、持久化、插件入口别名和全部折叠/隐藏等情况。
- 底部入口回归测试覆盖 ID 隔离、统一排序/折叠/显隐/重置、元素树投影、原动作插槽复用、无重复底部渲染和停用恢复；使用轻量 React/Slot 替身，不代替真实页面交互验证。
- 使用开发测试依赖 `linkedom` 构造真实 `data-slot` / `display:contents` DOM 包装层，确认样式选择器命中原生按钮：菜单图标 14px、主侧边栏图标 16px，且不影响插件子面板中的按钮。该测试检查选择器和声明，不代替浏览器实际布局验证。
- 构建产物通过 JavaScript 语法检查，资源清单与原创 SVG 图标已检查。
- 新增配置 schema、名称投影、条件状态控件排除、完整配置写入、旧本地配置迁移、连续编辑、保存失败回退、只读状态及菜单样式回归测试。
- 当前本地目录已安装为插件；管理器再次安装返回 `already-installed`，未为强制重装而卸载插件或清除现有配置。本次服务端 schema 升级需重启确认。
- 缺少浏览器交互控制，真实菜单点击、键盘操作、重启保持及深浅主题视觉仍需人工确认；Slot 注册成功不等于完整界面验证。
