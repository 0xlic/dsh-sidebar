# 侧边栏管理 · dsh-sidebar

用于 DeepSeek Harness 的侧边栏导航管理插件。

## 使用

安装后刷新应用，在 **设置 → 侧边栏管理** 中操作：

- 分别调整主侧边栏功能入口、设置侧边栏页面的排列顺序。
- 拖动左侧六点手柄排序，也可聚焦手柄后使用上下方向键。
- 点击菜单名称可直接编辑，按 Enter 或离开输入框保存；清空或点击「恢复原名」恢复插件提供的名称，最多 80 字。
- 主侧边栏列表中包含可排序的「更多」，名称固定，不提供显隐开关；设置侧边栏不加入该分界线。
- 「更多」是收纳分界线：排在上面的菜单直接显示在侧边栏，排在下面的菜单只出现在「更多」菜单中；移回上方即可展开。
- 收入「更多」的菜单保持顺序、点击跳转和当前页面标记；原有的浏览/创建插件等菜单动作保留。
- 「更多」内的原生图钉会将该菜单移到分界线上方，并保存新的顺序；主侧边栏不再显示临时取消固定按钮，避免与持久化分界冲突。
- 名称、排序和分界位置均立即预览，异步保存到插件配置，无需额外点击应用；提供读取中、保存中、只读或失败反馈。保存失败时回退到服务端已确认的配置。
- 没有已保存分界时，「更多」默认位于末尾；已保存排序后，新注册的功能入口追加在后方，因此可能收入「更多」。折叠不会停用对应插件。

**工作区设置 → 工作区一键折叠**（默认开启）：控制「工作区」标题右侧的一键折叠按钮和视图菜单中的折叠项；关闭后两者隐藏或不可用，不影响原生工作区行的展开与折叠。

**工作区设置 → 活跃工作区标识**（默认开启）：工作区下有运行中（包括运行中的子代理）或等待交互的会话时，右侧显示原生会话同款状态圆圈；悬停、键盘聚焦或打开工作区菜单时隐藏，有固定标识时位于其左侧。状态实时更新，工作区折叠不影响标识；已完成但未读的会话不算活跃，会话可见性遵循归档筛选。工作区设置中的活跃工作区标识、置顶工作区、一键折叠和动态调整排序默认均开启；「仅显示固定工作区」筛选仍默认关闭。

侧边栏「工作区」标题右侧操作区最左侧新增 **一键折叠** 按钮（复用原生 chevron 几何与 regular 1px 线宽），与搜索、视图选项、新建工作区组成四个图标：点击一次折叠当前所有工作区（按工作区树时包括父工作区）。按钮只提供折叠，不提供展开；不做禁用或变浅处理，可反复点击，已折叠时再次点击保持折叠状态。按钮不挤占原生搜索、视图选项和新建工作区的操作区；搜索框展开后自动隐藏。

「视图选项」菜单同时提供 **折叠所有工作区** 项，与标题按钮共享同一份原生展开状态；同样只折叠、不展开，也可反复点击。两者都只写入展开状态，不修改工作区注册表、会话或插件配置；单列表模式下按钮和菜单项均不显示或不可用。

侧边栏「视图选项」的「筛选会话」下方新增 **筛选工作区 → 仅显示固定工作区**：勾选后只保留已置顶的工作区及其会话，再次点击即可取消。该筛选仅在「按工作区」分组时生效，切换为「按工作区树」或「单列表」时菜单项显示为不可用且列表保持原样；被隐藏工作区的会话不会以「未分组」形式重现，其展开状态与手动会话顺序也会保留。

主侧边栏的「新会话」、底部头像设置及底部插件动作保留原有位置，不属于功能入口排序列表。旧配置中已有的「更多」位置继续保留；没有该位置时默认追加在末尾。旧 hidden 和底部动作投影配置不再使用。

## 保存范围

名称、排序、更多分界位置及工作区设置统一保存在 DSH 当前 profile 的本插件 `config.preferences` 中，通过公开的 `configForms` 服务读写。DSH 配置编辑器将变更写入当前 profile 的配置补丁，而不是修改本插件随包发布的配置模板。相同 profile 的其他浏览器也读取这份配置，刷新和重启后保留；不同 profile 仍互相独立。并发修订、写入权限及原子持久化由 DSH settings 服务处理；客户端提交完整 preferences 字段，确保清空名称及重置真正删除旧覆盖。

旧版浏览器配置 `dsh-sidebar.preferences.v1` 仅用于一次性迁移：当服务端没有 preferences、当前连接可写时，将旧名称/排序/显隐写入插件配置；只有服务端确认保存成功后才删除旧本地数据。服务端已有配置（包括显式恢复默认后的空配置）时，不用本地数据覆盖它。浏览器存储不可用不影响新配置的正常保存。

本次升级增加了服务端配置 schema，建议重启 DSH 一次再使用。若管理页提示「插件配置尚不可用」，请重启应用，而非只刷新页面。后续偏好修改为动态配置，无需再次重启。

## 开发

仅依赖 DSH 使用的 `@deepseek-ai/schemastery` 配置 schema 库，不修改 DSH 安装目录或原有插件。

```sh
npm ci --ignore-scripts
npm run build
npm test
```

使用 Harness 的插件管理器安装本目录即可。本地目录以链接方式安装，不要删除或移动工作目录。修改客户端代码后重新构建，并刷新应用；是否需要重启取决于插件管理器返回的安装状态。

## 实现与兼容性

针对 DSH `0.2.2-rc.2` 安装版本的导航源码实现。当前没有公开的全局导航分组接口，因此使用可撤销的版本相关适配层：在原注册项上包装组件，投影 `usePanels` / `useSections` 的顺序与名称；主侧栏保留原生 pin Hook 调用，但忽略其临时状态，按照持久化的「更多」分界派生展示。

侧栏元素树投影只调整原生 PanelRow 的可见性和原生 More 的 entries / 固定回调，不重复声明任何子 Slot，不引入 ID 别名。包括「插件」在内的面板均保留真实 ID、图标、选中状态与跳转；原生 More 的浏览/创建插件动作不变。菜单内固定操作将项目移到分界线上方，写入同一份配置。底部动作原样保留，不纳入排序。若无法识别原生 More，投影不折叠入口，避免导航无法访问。此适配层不是官方稳定扩展接口。

不使用 DOM 查询或改写，不导入 Harness 客户端内部模块，不改写方法原型。卸载时恢复组件引用并清理订阅、事件监听；展示偏好保留以供重新启用。更新客户端代码后须刷新整个应用页面。

此方式依赖原有组件的快照 Hook 名称及可写的组件引用，DSH 更新后若结构改变需重新验证。本插件保护的是自身导航入口，用户仍然可以从插件管理器主动停用或卸载本插件。
